Access in Plotra is set in two places and nowhere else: the workspace, and the project. This page lists what each role can do, checked against what the server allows. How to invite, share and change roles is on [Working together](/docs/collaboration) and [Your account and workspaces](/docs/settings/account).

## The roles

**Workspace roles** apply to every project in the workspace. They are given in the workspace's settings.

| Role | Who it is for |
| --- | --- |
| **Owner** | Whoever created the workspace, and anyone an owner promotes. Runs everything, including the plan. |
| **Admin** | Runs the workspace's people, projects and settings, but not its plan, and can't delete it. |
| **Member** | Writes in every project. |

**Project roles** apply to one project. They are given in that project's Share dialog, to any email address, in or outside the workspace.

| Role | Who it is for |
| --- | --- |
| **Editor** | A co-writer or editor who should work in this project and see no other. |
| **Commenter** | A beta reader. |
| **Viewer** | Someone who only reads. |

Someone who has a project role and isn't a member of the workspace is a **guest** there.

There are no roles or permissions on single notes or folders. Everything in a project follows the project.

## The five actions

Every check the server makes comes down to one of five actions on a project.

| Action | Means |
| --- | --- |
| **Read** | Open the project and everything in it |
| **Comment** | Write comments, reply, resolve, react, answer questionnaires |
| **Edit** | Change the text and the structure of the project |
| **Delete** | Trash notes, restore them and delete them for good |
| **Manage** | Change the project's settings and who can open it |

Each role is a fixed set of them.

| | Read | Comment | Edit | Delete | Manage |
| --- | --- | --- | --- | --- | --- |
| Viewer | Yes | | | | |
| Commenter | Yes | Yes | | | |
| Editor | Yes | Yes | Yes | Yes | |
| Member | Yes | Yes | Yes | Yes | |
| Admin | Yes | Yes | Yes | Yes | Yes |
| Owner | Yes | Yes | Yes | Yes | Yes |

So inside a project an editor and a workspace member can do the same things, and so can an admin and an owner. The differences between them are at the level of the workspace: see [The workspace](#the-workspace) below.

### Someone with two roles

A person can be a workspace member and also have a project role, for example a member the project was also shared with as a viewer. They get the actions of both, so whichever role lets them do more wins. A project role never takes anything away from a workspace member: sharing a project with a member as a viewer does not make it read-only for them.

A workspace role can't be narrowed for one project. To keep someone out of a project, they must not be a member of its workspace; share the projects they should see with them one by one.

## In a project

In the tables below, **Viewer**, **Commenter** and **Editor** are project roles, and **Member**, **Admin** and **Owner** are workspace roles.

| Use every view, search, links, **Mentioned in** and hover previews | Yes | Yes | Yes | Yes | Yes | Yes |

A viewer reads everything and can take it away as an export. Share a project as viewer only with people you would hand the file to.

Two exceptions:

- **A locked note.** A note in a locked stage can only be changed by its approvers and by admins and owners. For every other editor it becomes read-only, though they can still comment. See [Review and editorial](/docs/modules/editorial).
- **Menus that look available.** A few items aren't greyed out for people who can't use them, such as **Duplicate** in the binder for a viewer. The server refuses the action and nothing changes.

## The workspace

A guest has no workspace role, so nothing in this table applies to them: they can't open the workspace's home page at all.

| | Guest | Member | Admin | Owner |
| --- | --- | --- | --- | --- |
| See the workspace's home page and open every project in it | | Yes | Yes | Yes |
| Create a project, from scratch, from a template or from a sample | | Yes | Yes | Yes |
| Open the workspace's settings, and see its General tab and member list | | Yes | Yes | Yes |
| Rename the workspace or change its web address | | | Yes | Yes |
| Leave the workspace | | Yes | Yes | Yes |
| See open invitations | | | Yes | Yes |
| Invite people as member or admin, cancel an invitation | | | Yes | Yes |
| Change a role between member and admin | | | Yes | Yes |
| Remove a member or an admin | | | Yes | Yes |
| Make someone an owner; change or remove an owner | | | | Yes |
| Switch AI on or off for the workspace | | | | Yes |
| See the plan and what the workspace uses | | | Yes | Yes |
| Upgrade, cancel, open **Manage billing** | | | | Yes |
| Delete the workspace | | | | Yes |

Things that apply to everyone with a role in the workspace:

- Nobody can change their own role or remove themselves. To go, [leave the workspace](/docs/settings/account#general); the only owner can't leave.
- Removing someone from the workspace also removes every project in it that was shared with them directly.
- Deleting a project is for admins and owners, under **Project settings → General**.

Anyone with an account can create a workspace of their own and is its owner, whatever roles they hold elsewhere.

## A visitor with the read-only link

A project's [read-only link](/docs/collaboration/sharing#read-only-links) needs no account, so a visitor has no role. Whoever holds the link, signed in or not, gets the same page.

| | Visitor with the link |
| --- | --- |
| Read every note outside the trash, with its title, synopsis, tags and properties | Yes |
| Read notes that are not yet revealed, and passages tagged for a later release or "Never" | Yes. The link ignores the spoiler horizon. |
| Follow links between notes | Yes |
| See attached images that were inserted into notes | Yes |
| Open other attached files (PDFs, clipped pages) | No |
| See canvases, timelines and dialogues | No. They are listed, with a note to open the project in Plotra. |
| See the trash | No |
| See comments, suggestion marks, versions, activity, or who is online | No |
| Use views, search, or the spoiler horizon | No |
| Comment, edit or export | No |
| Use the link after it is switched off or reset | No |

Only admins and owners can create the link, and it is off until one of them switches it on.

## When access changes

| Change | When it takes effect |
| --- | --- |
| A project role is changed or removed | On the person's next request. A note they have open stops receiving and sending live changes within ten minutes. |
| A member is removed from the workspace | The same. |
| The read-only link is switched off or reset | At once. Nothing is cached. |
| Someone is promoted | When they next load the project. |
